# WebGPT Bridge v0.4.5 Runtime Governance Design

## Status
Approved for implementation on 2026-08-28. Baseline is v0.4.4 commit `97469f91730e26f3cb903e7701c611a794101622`. v0.4.4 tags/releases are immutable; all changes land in v0.4.5+.

## Goals

- Replace loose Desktop Host process ownership with a single runtime lifecycle authority.
- Define `connected` from actual Agent and tunnel readiness, not child-process liveness.
- Remove repeated expensive startup work without weakening AppContainer/Seatbelt enforcement.
- Convert repeated Windows trusted runtime staging into an immutable, content-addressed Host-owned cache.
- Fix macOS node-pty packaged PTY execution at build time before code signing.
- Add Host-owned diagnostics that expose product state without broad host introspection or secrets.
- Replace full-log IPC refresh with bounded incremental delivery and deterministic resynchronization.
- Make Stop, Quit, Restart, and Update Install share one bounded, awaited teardown contract.
- Preserve validated Windows dependency lifecycle, Goal cancellation, process-tree cleanup, approval boundaries, updater policy, and window-close-to-tray behavior.

## Non-goals

- No daemon/service rewrite.
- No weakening of AppContainer, Seatbelt, approval policy, workspace boundaries, or safe-storage handling.
- No runtime chmod/self-repair inside signed macOS app bundles.
- No unconditional node-pty beta upgrade.
- No arbitrary host diagnostic query API.
- No unbounded persistent logging system.
- No mutation of v0.4.4 tags or release artifacts.

## Architecture

`src/main.cjs` becomes a composition root. It wires Electron, settings, UI/tray IPC, UpdateService, AppLifecycleCoordinator, RuntimeSupervisor, HostDiagnosticsProvider, and HostLogBuffer. It no longer owns loose Agent/tunnel/broker process variables or performs startup/shutdown orchestration directly.

### RuntimeSupervisor

The Supervisor is the only owner of runtime lifecycle. States are:

`stopped -> preparing -> agent_starting -> agent_ready -> tunnel_starting -> connected`

with `degraded`, `failed`, and `stopping` as explicit exceptional/teardown states.

Rules:

1. `connected` requires Agent local health readiness and tunnel `/readyz` HTTP 200.
2. Start is single-flight. Duplicate starts share one transaction.
3. Stop/shutdown can cancel an in-progress start; no new resources may be acquired after cancellation.
4. Restart is an exclusive transaction; shutdown outranks restart, which outranks start/recovery.
5. Acquired resources are tracked in a ledger and released in reverse order.
6. Unexpected child exits are state events. Expected exits during stop/shutdown are not failures.
7. Runtime recovery is bounded. Initial policy: at most three attempts with approximately 1s, 3s, and 10s backoff; a stable connected period resets the budget.
8. No high-frequency external readiness polling. Readiness is bounded at transitions; runtime primarily follows child lifecycle events.
9. Legacy status booleans may remain temporarily for compatibility, but UI/tray connection state derives from Supervisor state.

### AppLifecycleCoordinator

The AppLifecycleCoordinator owns Electron-level Quit and Update Install while delegating runtime teardown to the Supervisor.

- `stop(reason)` tears down runtime and remains restartable.
- `shutdown(reason)` disables new start/recovery operations and is single-flight.
- First ordinary `before-quit` prevents default, starts shutdown, then re-enters `app.quit()` only after teardown reaches a terminal result.
- A native-quit gate prevents recursive `before-quit` handling.
- Update Install only calls `quitAndInstall()` after confirmed runtime shutdown. If shutdown cannot be confirmed, installation is refused.
- Ordinary explicit Quit remains bounded; after graceful + force cleanup attempts, unresolved cleanup is recorded as `SHUTDOWN_INCOMPLETE` rather than hanging forever.
- Normal window close still hides the window while the app remains running.

### StartupPreflight

`StartupPreflight.prepare()` produces an immutable `PreflightResult` used for the entire start transaction. It owns structural validation and delegates expensive preparation to dedicated services.

Every start performs cheap current-state checks: settings parse/validation, workspace/runtime/tunnel paths, runtime-key availability/decryption, profile/tunnel-id validation, and fast identity checks.

Expensive operations execute only when corresponding identities change: Node version probing, full sandbox verification, Windows host-preparation proof, trusted runtime cache build, strong hashing, and tunnel profile materialization.

### NodeRuntimeResolver

Candidate priority remains compatible with v0.4.4: explicit settings, `LPC_NODE_PATH`, bundled Node, platform-known candidates, then PATH.

- Explicit configured Node that exists but is invalid/unsupported fails precisely and does not silently fall back.
- Automatic candidates may fail and continue to the next candidate.
- Version probing becomes asynchronous and bounded; Electron main is not synchronously blocked by repeated `--version` calls.
- Host-owned cache binds version evidence to exact FileIdentity. Unchanged identities reuse the result.
- Packaged bundled Node should use a build-generated runtime manifest so warm startup does not execute `node --version`.

### SandboxAttestationService

A successful native sandbox verification may be reused only when the current exact security subject matches a Host-owned attestation.

The attestation subject is versioned and includes security-relevant product/Agent identity, platform/arch, backend/helper identity, verification/policy identity, `allowNetwork`, workspace boundary identity, runtime identity, and Windows host-preparation identity/generation where applicable.

Rules:

- Proofs are stored under trusted Desktop Host data, never a normal model-writable workspace.
- Success publication is atomic; failed/incomplete verification never creates reusable proof.
- Schema/parse/fingerprint mismatch is a cache miss and triggers full verification.
- Full verification failure is fail-closed.
- Network and no-network sandboxes have independent evidence.
- Verification only runs probes required by the active verification requirements; irrelevant loopback/external probes are skipped.
- Live verification evidence and cached evidence pass through the same strict promotion validation.

### TrustedRuntimeCache

Windows Node/npm child runtime staging becomes Host-owned, immutable, content-addressed storage.

The key binds source RuntimeIdentity, cache schema, preparation algorithm/security version, platform, and arch.

Build protocol:

1. Build in a random temporary directory.
2. Copy exact runtime payload and apply required security preparation/ACLs.
3. Build/validate manifest and reject unexpected symlink/junction/reparse-point entries.
4. Perform minimum runtime validation.
5. Write metadata.
6. Atomically publish to the content key.

Published keys are never modified in place. Corrupt entries are rejected/quarantined and rebuilt. Dependency lifecycle semantics remain unchanged; only trusted runtime resolution switches from repeated copy/staging to `TrustedRuntimeCache.ensure()`.

### TunnelProfileManager

Tunnel profile generation becomes Host-owned declarative materialization instead of unconditional `init --force` on every start.

- WebGPT Bridge uses a dedicated profile directory under Host user data.
- Desired profile fingerprint includes generation schema, tunnel-client identity/format contract, profile name, tunnel id, MCP URL, health-listener configuration, and runtime-key reference form.
- Runtime key secret values are never written to profile metadata/fingerprint/logs.
- Exact profile fingerprint hit skips `init`; `run --profile` is started directly.
- Profile changes call official tunnel-client `init` through one controlled materialization function, then atomically publish Host metadata only after success.
- Tunnel crash/retry normally retries `run`, not blind `init --force`.
- Profile existence is never connection readiness; `/readyz` remains authoritative.

### HostDiagnosticsProvider

The trusted Desktop Host exposes a fixed-schema, read-only diagnostic snapshot of WebGPT Bridge-owned state. It does not execute arbitrary `ps`, `tasklist`, registry, `launchctl`, filesystem, or process queries on request.

Full Host snapshot may include product-owned paths/PIDs. MCP-facing `host_diagnostics({})` receives a sanitized projection with no runtime key, bearer token, proxy credentials, environment dump, full child argv, or broker socket path.

Diagnostic groups include Desktop/build identity, Supervisor/lifecycle state, Agent health, tunnel readiness, sandbox evidence source, Windows host prep, trusted runtime cache, native PTY payload state, updater state, and startup phase timings. Failures use stable machine-readable reason codes.

### HostLogBuffer and IPC

Host owns the only in-memory log truth: a 600-entry bounded buffer. Each entry receives a monotonic sequence number and the stream has a startup/reset generation id.

- Initial/recovery path uses a bounded snapshot containing generation, firstSeq, lastSeq, and entries.
- Normal path sends only contiguous bounded append batches.
- Renderer detects generation changes or sequence gaps and performs a single-flight snapshot refresh.
- Reset creates a new generation.
- Batches and individual lines have explicit bounds; truncation is marked.
- Renderer incrementally appends/removes nodes and only auto-scrolls when the user was already near the bottom.

### macOS node-pty packaging

The installed v0.4.4 artifact has `node-pty/prebuilds/darwin-arm64/spawn-helper` and `darwin-x64/spawn-helper` at mode `0644`, causing packaged PTY `posix_spawnp failed`.

Fix contract:

- Keep node-pty 1.1.0 unless independent evidence requires a dependency change.
- Add a build-time payload utility and electron-builder `afterPack` hook.
- On macOS staged unsigned `.app`, require both Darwin `spawn-helper` and `pty.node` payloads. Missing, symlinked, escaped, or malformed payload fails the build.
- Normalize only execute bits with `mode | 0o111`; assert final helper execute bits.
- Never modify the signed app at runtime.
- After builder/signing, an independent read-only artifact inspector rechecks final payloads.
- Packaged acceptance launches real Node PTY and shell PTY with input/output/exit/kill checks.
- Universal builds statically validate both arm64 and x64 payloads; execution smoke runs on the CI runner architecture.

## Shared primitives

Small shared utilities may provide FileIdentity, RuntimeIdentity, stable reason-code/result types, atomic JSON publication, and bounded child execution. They are implementation primitives only; trust decisions remain subsystem-specific. A sandbox attestation hit never authorizes a runtime cache entry, and a tunnel profile fingerprint is not a security attestation.

## Error handling

Core failures carry stable machine-readable codes and phase information. Representative codes include:

- `AGENT_HEALTH_TIMEOUT`, `TUNNEL_READY_TIMEOUT`, `TUNNEL_EXITED`
- `SANDBOX_ATTESTATION_INVALID`, `SANDBOX_VERIFICATION_FAILED`
- `TRUSTED_RUNTIME_CORRUPTED`
- `NODE_CONFIGURED_RUNTIME_INVALID`, `NODE_DISCOVERY_FAILED`
- `TUNNEL_PROFILE_MATERIALIZATION_FAILED`
- `NATIVE_PTY_PAYLOAD_INVALID`
- `START_CANCELLED_BY_STOP`, `START_CANCELLED_BY_QUIT`
- `SHUTDOWN_TIMEOUT`, `SHUTDOWN_INCOMPLETE`, `APP_SHUTTING_DOWN`

Logs render human-readable messages, but lifecycle/tests do not infer state from log text.

## Security invariants

1. AppContainer/Seatbelt enforcement is preserved.
2. Trusted proof/cache/profile locations are Host-owned and outside ordinary model-writable workspaces.
3. Cache corruption or proof mismatch never degrades to unverified reuse.
4. Runtime secrets never appear in diagnostics, cache keys, profile metadata, or command dumps.
5. `host_diagnostics` has no arbitrary selector/path/PID/query parameters.
6. macOS native payload repair happens before signing, never after.
7. Update Install is blocked if controlled runtime shutdown cannot be confirmed.

## Performance invariants

Warm unchanged startup must show evidence that repeated expensive operations are removed:

- Node version subprocess probes: 0 for unchanged known/bundled runtime.
- Full sandbox verification: 0 on exact valid attestation hit.
- Windows Node/npm runtime copy/build: 0 on immutable cache hit.
- Tunnel profile `init`: 0 on exact profile hit.

Agent health and tunnel `/readyz` remain actual per-start readiness checks.

## Acceptance matrix

### Cross-platform

- Supervisor state machine and single-flight lifecycle tests.
- Start cancellation and reverse rollback tests.
- Awaited Stop/Quit/Restart/Update teardown with bounded escalation.
- Warm/cold/change/corruption evidence for all caches.
- Sanitized Host diagnostics leak tests.
- Incremental log sequence/gap/reset/600-entry tests.
- Connected UI/tray derives from Supervisor readiness state.

### Windows

- AppContainer remains enforced.
- Cold live sandbox verification and warm attestation hit.
- Windows host-preparation apply/remove/repair regressions remain green.
- Trusted runtime second use is a cache hit.
- Dependency install/lifecycle, Goal cancellation, tree kill, and no-orphan acceptance remain green.
- Existing Windows PTY acceptance remains green.
- NSIS installer lifecycle smoke remains green.

### macOS

- Seatbelt remains enforced.
- Cold live sandbox verification and warm attestation hit.
- Final packaged arm64/x64 `spawn-helper` are executable and corresponding `pty.node` files exist.
- Real packaged Node PTY and shell PTY succeed without `posix_spawnp failed`.
- PTY/input/kill and Desktop Stop/Quit leave no known orphan.

### CI and release

A v0.4.5 candidate is not complete until focused tests, fresh exact-commit CI, final artifact inspection, and real installed Windows/macOS acceptance agree on the same build identity. Release metadata must identify version/commit/platform/arch. v0.4.4 remains untouched.
