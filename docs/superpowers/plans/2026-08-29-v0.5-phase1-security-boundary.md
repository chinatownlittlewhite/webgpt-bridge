# WebGPT Bridge v0.5 Phase 1 Security Boundary Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Establish the v0.5 security-boundary foundation by recording the v0.4.11 baseline, closing generic Host-file authorization bypasses, enforcing one Desktop owner, and authenticating/versioning the App-owned broker without changing unrelated runtime behavior.

**Architecture:** Keep the existing Electron + Agent split and evolve it incrementally. `local_read`/`local_list` keep their public names and existing `accessId` field, but `accessId` becomes a real session-scoped Host capability issued by the Desktop after native approval. Desktop single-instance ownership is established before runtime services start. Broker requests move from unauthenticated newline-delimited request messages to an authenticated session handshake followed by the same bounded request/response framing.

**Tech Stack:** Electron 40, Node.js >=20 Agent Runtime, CommonJS Desktop modules, ESM Agent modules, `node:test`, Unix domain sockets / Windows named pipes, existing native approval and sandbox infrastructure.

**Spec:** `docs/superpowers/specs/2026-08-29-v0.5-security-architecture-slim-ui-design.md`

## Global Constraints

- Baseline is Desktop v0.4.11 / Agent Runtime v0.9.3 at commit `05e9faf192fa8d6341f991d99e15deb68a2b1338`.
- Existing users must not reset settings, runtime keys, workspace selection, handoff data, or valid Goal state.
- Existing MCP capabilities must not be removed merely to simplify implementation.
- Existing shell, privilege-escalation, sensitive-path, sandbox, approval, and process-isolation boundaries must not be weakened.
- macOS and Windows remain formal release targets.
- No Electron replacement, UI framework migration, first-run dependency download, UPX, or unrelated feature expansion in this phase.
- Existing App identity and user-data compatibility remain unchanged.
- Changes land incrementally; every task ends with focused tests and a commit.
- Generic Host access outside the workspace becomes capability-scoped. Desktop/Downloads/Documents cannot be reached through generic `local_read`/`local_list` without the same class of user authorization required by the dedicated known-folder tools.
- System roots remain denied. Sensitive writes/execution remain denied. Shells and privilege escalation remain model-disabled.
- Broker secrets must never appear in logs, capabilities, diagnostics, handoff, project files, or test snapshots.
- This phase does **not** implement the canonical Security Policy Core, Goal Store v2, file transaction recovery, Tool Registry, Host-wide decomposition, packaging slimming, or renderer redesign. Those remain later phases in the approved spec.

## Stable Interfaces Introduced in This Phase

### Host capability store

```js
createHostCapabilityStore({
  generation,
  policyVersion,
  now = Date.now,
  randomId,
})
```

Returns:

```js
{
  issue({ root, operations, ttlMs, maxUses, className }),
  authorize({ accessId, path, operation }),
  revoke(accessId),
  clear(),
  size(),
}
```

`issue()` returns a frozen public descriptor:

```js
{
  accessId,
  root,
  operations,
  expiresAt,
  remainingUses,
  className,
}
```

`authorize()` returns the canonical target path on success and throws a stable error with `code` equal to one of `HOST_CAPABILITY_REQUIRED`, `HOST_CAPABILITY_EXPIRED`, or `HOST_CAPABILITY_SCOPE_MISMATCH` on failure. Single-use capabilities are consumed only after a successful scope/operation match.

### File broker additions

`createLocalFileBroker()` receives:

```js
{
  capabilityStore,
  workspaceRoot,
  knownFolderRoots,
  ...existingOptions
}
```

Generic `list({ path, accessId })` and `read({ path, accessId })` rules:

1. system/sensitive immutable deny remains authoritative;
2. workspace path is allowed without `accessId`;
3. known-folder path requires a valid capability even if the raw path policy says ordinary;
4. any other Host path outside the workspace requires a valid capability;
5. capability root and operation must cover the requested canonical target.

### Ordinary Host access request

Additive broker method/tool:

```text
local_request_host_access
```

Input schema:

```js
{
  path: string,
  operation: "list" | "read"
}
```

It never accepts a caller-provided TTL, use count, permission class, bypass flag, or approval result. Desktop chooses the grant shape after native confirmation.

### Broker bootstrap

Desktop generates on each primary lifecycle:

```js
{
  protocolVersion: 1,
  sessionId: crypto.randomUUID(),
  secret: crypto.randomBytes(32).toString("base64url")
}
```

Trusted Agent child environment receives:

- `LPC_LOCAL_BROKER_PROTOCOL=1`
- `LPC_LOCAL_BROKER_SESSION=<uuid>`
- `LPC_LOCAL_BROKER_SECRET=<secret>`

The secret is not exposed through `get_capabilities` or diagnostics.

Authentication uses a challenge/response so the broker secret itself never crosses the socket/pipe. The frames are:

```json
{"type":"hello","protocolVersion":1,"sessionId":"...","agentVersion":"0.9.x"}
{"type":"challenge","protocolVersion":1,"sessionId":"...","nonce":"..."}
{"type":"authenticate","protocolVersion":1,"sessionId":"...","proof":"HMAC-SHA256(base64url)"}
{"type":"hello_ok","protocolVersion":1,"sessionId":"..."}
```

The proof is `HMAC-SHA256(secret, protocolVersion + "\n" + sessionId + "\n" + agentVersion + "\n" + nonce)` encoded as base64url. Nonces are cryptographically random and valid only for the current connection. Only after `hello_ok` may the connection accept/request normal `{id, method, params}` frames. The server closes on missing/invalid auth or unsupported protocol before dispatching a method.

```js
const fs = require("node:fs");
const path = require("node:path");

function treeBytes(target) {
  const stat = fs.lstatSync(target, { throwIfNoEntry: false });
  if (!stat) return 0;
  if (stat.isSymbolicLink()) return 0;
  if (stat.isFile()) return stat.size;
  if (!stat.isDirectory()) return 0;
  return fs.readdirSync(target).sort().reduce((sum, name) => sum + treeBytes(path.join(target, name)), 0);
}

function collectPackageSizes(rootPath) {
  return {
    totalBytes: treeBytes(rootPath),
    frameworksBytes: treeBytes(path.join(rootPath, "Contents", "Frameworks")),
    resourcesBytes: treeBytes(path.join(rootPath, "Contents", "Resources")),
    appAsarBytes: treeBytes(path.join(rootPath, "Contents", "Resources", "app.asar")),
    appAsarUnpackedBytes: treeBytes(path.join(rootPath, "Contents", "Resources", "app.asar.unpacked")),
    tunnelClientBytes: treeBytes(path.join(rootPath, "Contents", "Resources", "tunnel-client")),
  };
}

if (require.main === module) {
  const rootPath = process.argv[2];
  if (!rootPath || !path.isAbsolute(rootPath)) throw new Error("Usage: node scripts/report-package-size.cjs <absolute-app-root>");
  process.stdout.write(`${JSON.stringify(collectPackageSizes(rootPath), null, 2)}\n`);
}

module.exports = { collectPackageSizes, treeBytes };
```

function authorize(inputPath, operation, accessId) {

async function requestHostAccess({ path: inputPath, operation } = {}) {
  if (operation !== "list" && operation !== "read") throw new Error("Host access only supports list/read");
  const classified = policy(inputPath, { operation });
  if (classified.scope === "workspace") throw new Error("workspace access does not require a Host capability");
  if (classified.scope === "system") throw codedPolicyError(classified);
  if (classified.scope === "sensitive") throw new Error("use local_request_sensitive_access for sensitive paths");
  const approved = await confirm({
    kind: "host-path-access",
    path: classified.path,
    operation,
    permissionClass: `host-path:${operation}:${classified.path}`,
  });
  if (!approved) throw new Error("用户取消了工作区外本机路径访问请求。");
  const grant = capabilityStore.issue({
    root: classified.path,
    operations: [operation],
    ttlMs: 5 * 60_000,
    maxUses: 100,
    className: `host-path-${operation}`,
  });
  return { accessId: grant.accessId, path: classified.path, operation };
}

function establishSingleInstanceOwnership({ app, activatePrimary }) {
  if (!app || typeof app.requestSingleInstanceLock !== "function") throw new TypeError("Electron app ownership API is required");
  if (typeof activatePrimary !== "function") throw new TypeError("activatePrimary must be a function");
  if (!app.requestSingleInstanceLock()) {
    app.quit();
    return Object.freeze({ primary: false, dispose() {} });
  }
  const onSecondInstance = () => activatePrimary();
  app.on("second-instance", onSecondInstance);
  return Object.freeze({
    primary: true,
    dispose() { app.removeListener("second-instance", onSecondInstance); },
  });
}

module.exports = { establishSingleInstanceOwnership };

- [ ] **Step 4: Implement the shared canonical protocol helpers**

Create `shared/local-broker-protocol.cjs` with no Electron dependency:

```js
const crypto = require("node:crypto");
const BROKER_PROTOCOL_VERSION = 1;

function createBrokerBootstrap({
  randomSessionId = crypto.randomUUID,
  randomSecret = () => crypto.randomBytes(32).toString("base64url"),
} = {}) {
  return Object.freeze({
    protocolVersion: BROKER_PROTOCOL_VERSION,
    sessionId: randomSessionId(),
    secret: randomSecret(),
  });
}

function proofPayload({ protocolVersion, sessionId, agentVersion, nonce }) {
  return `${protocolVersion}\n${sessionId}\n${agentVersion}\n${nonce}`;
}

function createBrokerProof({ protocolVersion, sessionId, agentVersion, nonce, secret }) {
  return crypto.createHmac("sha256", secret).update(proofPayload({ protocolVersion, sessionId, agentVersion, nonce })).digest("base64url");
}
```

`createBrokerChallenge()` validates hello type/version/session and returns a cryptographically random per-connection nonce. `verifyBrokerProof()` recomputes the expected HMAC and compares fixed-length decoded MAC bytes with `crypto.timingSafeEqual`; malformed/length-mismatched proofs fail auth. Return only `{ok:false, code}` for failures.

Desktop imports this module with ordinary `require("../shared/local-broker-protocol.cjs")`. Agent ESM imports the **same physical module** via:

```js
import { createRequire } from "node:module";
const require = createRequire(import.meta.url);
const brokerProtocol = require("../../shared/local-broker-protocol.cjs");
```

The relative path is intentionally valid from both `agent-runtime/src/*` and copied `agent-runtime/dist/*`. Do not duplicate `proofPayload()` or the protocol version inside Agent source.
