# v0.4.5 Host Diagnostics and Incremental Logs Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Expose fixed-schema product-owned Host state for support/acceptance and replace full 600-line IPC refreshes with sequence-safe incremental logging.

**Architecture:** `HostDiagnosticsProvider` projects immutable snapshots from owned services and sanitizes the MCP-facing view. `HostLogBuffer` is the sole in-memory log truth and publishes bounded snapshot/append events with generation + sequence recovery.

**Tech Stack:** Node.js CommonJS, Electron IPC/contextBridge, Agent local broker, node:test.

**Spec:** `docs/superpowers/specs/2026-08-28-v0.4.5-runtime-governance-design.md`

## Global Constraints
- `host_diagnostics` accepts no arbitrary path/PID/query selectors.
- Never expose runtime key, bearer tokens, proxy credentials, full environment, child argv, or broker socket path to MCP.
- Keep at most 600 visible log entries.
- Normal log path sends only new entries; snapshot is bootstrap/recovery.
