# macOS Variants and Size Budget Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish and verify macOS arm64, x64, and Universal packages while keeping Universal as the updater target and recording attributable package-size growth.

**Architecture:** Build each macOS architecture as an explicit package variant. The variant is projected into the Electron Builder `afterPack` hook so node-pty normalization and pruning retain only the required Darwin native payload for single-architecture packages while Universal keeps both. CI builds each architecture on a native GitHub runner, uploads variant-specific release artifacts, and emits component-size JSON that can be compared with the previous formal release when available.

**Tech Stack:** Node.js 22+, Electron Builder 26.15.3, node:test, GitHub Actions, macOS `lipo`.

**Spec:** `docs/superpowers/specs/2026-08-29-v0.5-security-architecture-slim-ui-design.md`

## Global Constraints

- Continue publishing a macOS Universal artifact.
- Add macOS arm64 and macOS x64 alternatives.
- Architecture-specific packages include only required target native payloads; Universal retains both Darwin architectures where required.
- Do not introduce first-run network dependency installation.
- Do not use UPX.
- Pruning happens before signing/notarization.
- Release CI must record total app, framework, Agent runtime, tunnel payload, node-pty/native payload, and `app.asar` sizes.
- Unexpected material growth must be attributable rather than silently accepted.
- `latest-mac.yml` remains bound to the Universal updater ZIP.
