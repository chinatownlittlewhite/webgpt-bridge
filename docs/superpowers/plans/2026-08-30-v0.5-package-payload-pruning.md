# WebGPT Bridge v0.5 Package Payload Pruning Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Remove target-platform-irrelevant and development-only Agent/native payloads from packaged Desktop artifacts without changing runtime capabilities, security boundaries, or the current macOS Universal contract.

**Architecture:** Keep the installed dependency tree unchanged for development and build preparation. Add one deterministic post-pack pruner that operates only inside the packaged `Contents/Resources/app.asar.unpacked/agent-runtime` tree, runs after macOS PTY normalization, and preserves the native payload required by the target platform. This phase is platform-level only: macOS keeps both Darwin `node-pty` architectures so the existing Universal merge/inspection path remains unchanged; architecture-specific pruning belongs to the next release-variant phase.

**Tech Stack:** Node.js CommonJS, Electron Builder `afterPack`, `node:test`, existing packaged PTY inspector/smoke gates.

**Spec:** `docs/superpowers/specs/2026-08-29-v0.5-security-architecture-slim-ui-design.md`

## Global Constraints

- Existing users upgrade without resetting settings, runtime keys, workspace selection, handoff data, or valid Goal state.
- Existing MCP capabilities are not removed merely to simplify implementation or reduce package size.
- Existing shell, privilege-escalation, sensitive-path, sandbox, approval, and process-isolation boundaries are never weakened.
- macOS and Windows remain formal release targets with real packaged acceptance.
- Do not introduce first-run dependency installation or any new runtime dependency.
- Do not use UPX.
- Pruning runs before signing/notarization.
- macOS retains both `darwin-arm64` and `darwin-x64` PTY payloads in this phase so the current Universal artifact remains compatible.
- Windows x64 retains the required `win32-x64` PTY payload and bundled trusted Node/runtime-host components.

### Task 1: Define the bounded packaged-runtime pruner

**Files:**
- Create: `scripts/package-payload-pruner.cjs`
- Create: `test/package-payload-pruner.test.cjs`

**Interfaces:**
- Produces: `prunePackagedAgentRuntime({ resourcesRoot, platform, arch }) -> { removedBytes, removedPaths }`.
- `platform` accepts only `"darwin"` or `"win32"`; Windows packaging accepts only `arch: "x64"` in this phase.
- The function may delete only descendants of `Contents/Resources/app.asar.unpacked/agent-runtime`.

- [ ] **Step 1: Write RED fixture tests**

Create a temporary packaged-runtime fixture containing runtime `dist`, production MCP dependencies, the development-only `@modelcontextprotocol/client`, Windows Host native payload, both Darwin PTY prebuilds, both Windows PTY prebuilds, PTY source/build metadata, tests, and source maps.

Assert macOS pruning:

```js
const result = prunePackagedAgentRuntime({ resourcesRoot, platform: "darwin", arch: "arm64" });
assert.equal(exists("node_modules/@modelcontextprotocol/client"), false);
assert.equal(exists("native/windows-host"), false);
assert.equal(exists("node_modules/node-pty/prebuilds/win32-x64"), false);
assert.equal(exists("node_modules/node-pty/prebuilds/win32-arm64"), false);
assert.equal(exists("node_modules/node-pty/prebuilds/darwin-arm64/pty.node"), true);
assert.equal(exists("node_modules/node-pty/prebuilds/darwin-x64/pty.node"), true);
assert.equal(exists("dist/server.js"), true);
assert.ok(result.removedBytes > 0);
```

Assert Windows x64 pruning removes both Darwin prebuilds and `win32-arm64`, while retaining `win32-x64`, `native/windows-host`, production dependencies, and `dist`.

Assert both platforms remove known development-only PTY directories/files (`deps`, `third_party`, `src`, `scripts`, `binding.gyp`), `*.test.js`, and `*.map` files under packaged Agent dependencies. Assert the operation is idempotent and rejects unsupported platform/arch values or a missing packaged Agent root.

- [ ] **Step 2: Run the focused test and verify RED**

Run: `node --test test/package-payload-pruner.test.cjs`

Expected: FAIL with `MODULE_NOT_FOUND` because `scripts/package-payload-pruner.cjs` does not exist.

- [ ] **Step 3: Implement minimal safe pruning**

Delete only fixed known paths plus recursively matched `*.map`/`*.test.js` files beneath `agent-runtime/node_modules`. Missing optional targets are skipped so a second run is idempotent. A missing/non-directory Agent root fails closed with `PACKAGE_PAYLOAD_INVALID`.
