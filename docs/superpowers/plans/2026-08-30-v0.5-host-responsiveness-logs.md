# v0.5 Host Responsiveness and Logs Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make GitHub health probing non-blocking on the Electron main thread and replace full-ring log retransmission with a bounded, sequence-safe incremental protocol.

**Architecture:** Extract GitHub authentication health into an async helper that preserves separate connectivity, binary-presence, and authentication facts. Replace the ad-hoc `logLines` array with one Host-owned log buffer that emits a bounded initial snapshot and monotonic append batches; the renderer maintains its own bounded presentation state, detects generation/sequence gaps, and performs one bounded snapshot resync.

**Tech Stack:** Node.js CommonJS, Electron IPC/contextBridge, vanilla browser JavaScript, node:test.

**Spec:** `docs/superpowers/specs/2026-08-29-v0.5-security-architecture-slim-ui-design.md`

## Global Constraints

- Existing shell, privilege-escalation, sensitive-path, sandbox, approval, and process-isolation boundaries are never weakened.
- Renderer remains HTML/CSS/vanilla JavaScript with no remote assets or heavy framework.
- Host remains authoritative for logs; renderer stores only a bounded presentation buffer.
- GitHub connectivity, binary readiness, and authentication remain distinct states.
- Normal log updates carry only new entries; full snapshots are bootstrap/recovery only.
- Log payloads remain bounded to at most 600 visible entries and do not expose new secrets.
- macOS Universal and Windows packaged acceptance remain hard gates.

### Task 2: Host incremental log buffer

**Files:**
- Create: `src/host-log-buffer.cjs`
- Modify: `src/main.cjs`
- Modify: `src/host/ipc-controller.cjs`
- Test: `test/host-responsiveness-logs.test.cjs`

**Interfaces:**
- Produces: `createHostLogBuffer({ capacity: 600, maxBatchEntries, maxBatchBytes })` with `append(source, data)`, `snapshot()`, `reset()`, and `subscribe(listener)`.
- Snapshot shape: `{ kind: "snapshot", generation, lastSeq, entries }`.
- Append shape: `{ kind: "append", generation, fromSeq, toSeq, entries }`.

- [ ] **Step 1: Write the failing test**

Assert that normal log publication no longer emits the full `logLines` ring, snapshots are bounded, sequences are monotonic, reset changes generation, append batches are contiguous/new-only, and oversized lines are explicitly truncated.

- [ ] **Step 2: Run test to verify it fails**

- [ ] **Step 3: Write minimal implementation**

Create the Host-owned ring buffer, coalesce same-turn append notifications into bounded batches, and make `host:logs` return only a snapshot. `reset()` publishes an empty snapshot with a new generation so stale renderer batches cannot cross resets.

- [ ] **Step 4: Run test to verify it passes**

Run: `node --test test/host-responsiveness-logs.test.cjs` and `npm run verify:desktop`.
Expected: PASS.

### Task 3: Renderer gap recovery and incremental DOM

**Files:**
- Create: `src/renderer/log-state.js`
- Modify: `src/renderer/index.html`
- Modify: `src/renderer/renderer.js`
- Modify: `src/preload.cjs` only if required by the fixed protocol surface
- Test: `test/renderer-log-protocol.test.cjs`

**Interfaces:**
- Produces: `createRendererLogState({ capacity, requestSnapshot, onSnapshot, onAppend })`.
- Consumes Host snapshot/append shapes from Task 2.

- [ ] **Step 1: Write the failing test**

Cover listener-before-snapshot bootstrap races, contiguous append, duplicate/overlap de-duplication, generation or sequence gaps causing exactly one snapshot recovery, and a visible buffer capped at 600 entries.

- [ ] **Step 2: Run test to verify it fails**

Run: `node --test test/renderer-log-protocol.test.cjs`
Expected: FAIL because the renderer currently expects full arrays and has no generation/sequence state.

- [ ] **Step 3: Write minimal implementation**

Load a browser/CommonJS-compatible pure log-state helper before `renderer.js`. Register the Host event listener before requesting the initial snapshot, queue bounded pre-bootstrap batches, accept only contiguous sequences, and use a single-flight resync on gaps. Render snapshots by replacement, normal batches by appending only new line nodes, trim oldest nodes above 600, and auto-scroll only when already near the bottom.

- [ ] **Step 4: Run test to verify it passes**

Run: `node --test test/renderer-log-protocol.test.cjs`, `node --test test/host-responsiveness-logs.test.cjs`, and `npm run verify:desktop`.
