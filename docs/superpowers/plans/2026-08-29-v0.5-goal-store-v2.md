# Goal Store v2 + v1 Migration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the v1 per-session JSON Goal store with a durable journal + snapshot v2 store while preserving the existing Goal controller API, fail-closed protected-effect semantics, and automatic readability/migration of valid v1 sessions.

**Architecture:** Keep `createFileGoalSessionStore()` as the public compatibility factory, but move durable persistence into a focused `goal-store-v2.js`. The existing controller already persists `session.inFlightMutation` before protected effects and clears it only when the result state is saved; v2 maps that pair to one durable journal mutation (`intent` then `commit`) without changing Goal tool behavior. Ordinary state saves/removes use their own intent+commit records, snapshots are atomically published only when no protected mutation is pending, and v1 files remain untouched after migration.

**Tech Stack:** Node.js >=20, ESM Agent Runtime, `node:fs`, `node:path`, `node:crypto`, `node:test`; no SQLite/native dependency.

**Spec:** `docs/superpowers/specs/2026-08-29-v0.5-security-architecture-slim-ui-design.md` §5 “Goal Store v2”.

## Global Constraints

- Baseline is Desktop v0.4.11 / Agent Runtime v0.9.3 on branch `continue/handoff-20260828-latest` after canonical Security Policy Core commit `881ce6c`.
- Preserve the current public store contract: `loadAll()`, `save(session)`, `remove(sessionId)`, `kind`, `persistent`, and `directory` remain usable by existing callers/tests.
- Preserve `.webgpt-bridge/goals` as the existing Goal state boundary; v2 lives at `.webgpt-bridge/goals/state-v2` so v1 `*.json` files can remain in place.
- Preserve current Goal controller semantics: an `inFlightMutation` must be durable before a protected tool/finish/pause/cancel effect and an uncertain effect must never be replayed automatically.
- Do not add SQLite, native modules, external dependencies, background services, or cross-process shell commands.
- Do not delete legacy v1 files during migration. Cleanup is explicitly out of scope.
- Corrupt/discontinuous v2 state must fail closed; it must not silently hydrate an empty Goal history.
- This phase does not implement crash-recoverable local file transactions, Goal verification profiles, Tool Registry, Host decomposition, packaging slimming, UI work, version bumps, tags, installers, or releases.
- All production behavior changes follow TDD: focused RED, minimal implementation, focused GREEN, then full regression/acceptance.

- [ ] **Step 3: Implement canonical record/checksum and durable append helpers**

Implement in `goal-store-v2.js`:

```js
const STORE_VERSION = 2;
const JOURNAL_VERSION = 1;

function canonicalize(value) {
  if (Array.isArray(value)) return value.map(canonicalize);
  if (!value || typeof value !== "object") return value;
  return Object.fromEntries(Object.keys(value).sort().map((key) => [key, canonicalize(value[key])]));
}

function digest(value) {
  return createHash("sha256").update(JSON.stringify(canonicalize(value))).digest("hex");
}

function checkedRecord(fields) {
  const body = { version: STORE_VERSION, journalVersion: JOURNAL_VERSION, ...fields };
  return Object.freeze({ ...body, checksum: digest(body) });
}
```

Use `openSync(..., "a")` / `writeSync` / `fsyncSync` / `closeSync` for every journal record. Atomic snapshot publication must write+fsync a same-directory temp file, rename it, then best-effort fsync the parent directory.

- [ ] **Step 4: Implement replay and compatibility methods**

Replay rules:

```text
valid snapshot -> sessions map + snapshot sequence
journal records must have valid checksum and strictly contiguous sequence
intent records register mutation identity
non-protected unmatched intents do not change committed state
protected intents carry the persisted inFlightMutation session and become visible immediately
commit records must match a known intent and then apply session/tombstone state
unmatched protected intent remains visible so existing controller restart logic fails closed
```

Ordinary `save()` and `remove()` append an intent, fsync it, append the commit, fsync it, then mutate in-memory committed state. Protected `save(sessionWithInFlightMutation)` appends/fsyncs only the protected intent and updates the visible state; the later marker-free save commits the same mutation.

- [ ] **Step 5: Implement safe snapshot publication/compaction**

After `snapshotEvery` committed mutations, and only when there is no pending protected mutation:

1. Write a checksummed snapshot containing the current sequence and sorted session array.
2. Fsync+rename it atomically and best-effort fsync `state-v2`.
3. Truncate `journal.log` with `openSync(..., "w")`, fsync, close.
4. Continue the next journal sequence from `snapshot.sequence + 1`.

- [ ] **Step 3: Move old per-file reader/writer behind a legacy helper**

Keep a bounded v1 reader for migration/fallback:

```js
function readLegacySessions(directory) {
  return fs.readdirSync(directory, { withFileTypes: true })
    .filter((entry) => entry.isFile() && entry.name.endsWith(".json"))
    .sort((a, b) => a.name.localeCompare(b.name))
    .flatMap((entry) => {
      try {
        const parsed = JSON.parse(fs.readFileSync(path.join(directory, entry.name), "utf8"));
        return parsed?.version === 1 && parsed.session && typeof parsed.session === "object"
          ? [structuredClone(parsed.session)]
          : [];
      } catch {
        return [];
      }
    });
}
```

Do not delete, rename, or rewrite the source legacy files.

- [ ] **Step 4: Implement transactional migration directory publication**

When `<goals>/state-v2` does not exist:

1. Read valid legacy sessions.
2. Create `<goals>/.state-v2-migrate-<uuid>`.
3. Build `metadata.json`, `snapshot.json`, `journal.log` there with `migrationComplete: true` only after all files are durable.
4. Re-open the temporary v2 directory with the same validation/replay code and compare imported session ids/count.
5. Rename the validated temp directory atomically to `<goals>/state-v2` and best-effort fsync `<goals>`.
6. Remove only the temporary migration directory on a pre-publication failure; legacy source files remain untouched.

If a migration cannot be published and valid v1 sessions exist, return a legacy-compatible store so those sessions remain readable/writable rather than presenting an empty history. If a completed `state-v2` exists, always prefer and validate it.

- [ ] **Step 4: Harden replay validation**

Reject with bounded errors when any v2 journal suffix has:

- invalid JSON,
- wrong store/journal version,
- checksum mismatch,
- non-integer or non-contiguous sequence,
- duplicate mutation id intent,
- commit without a matching intent,
- mismatched session id / operation / input hash between intent and commit,
- invalid protected intent without a bounded `inFlightMutation` session payload.

Never auto-complete an unmatched protected intent.
