# v0.4.5 Sandbox Attestation and Trusted Runtime Cache Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Reuse exact successful sandbox evidence and Windows trusted Node/npm runtime artifacts without weakening fail-closed security behavior.

**Architecture:** Host-owned versioned identities and atomic evidence/cache publication sit outside ordinary model-writable workspaces. Live verification remains the source of truth on cache miss; successful cached evidence must satisfy the same promotion contract.

**Tech Stack:** Node.js, Agent Runtime ESM, native AppContainer/Seatbelt adapters, node:test.

**Spec:** `docs/superpowers/specs/2026-08-28-v0.4.5-runtime-governance-design.md`

## Global Constraints
- AppContainer/Seatbelt remain enforced.
- No cache hit may be inferred from path/name alone.
- Parse/schema/fingerprint corruption becomes a miss; live verification failure remains fail-closed.
- Network and no-network sandbox evidence are independent.
- Published trusted runtime cache keys are immutable.
